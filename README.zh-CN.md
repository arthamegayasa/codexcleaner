# CodexCleaner

[English](README.md)

> Windows 版 Codex 越用越卡？启动转圈、界面假死、任务恢复失败，左侧栏还挂着删不掉的“幽灵任务”？  
> **CodexCleaner 会分别体检和整理本地任务历史与可重建性能缓存，让 Codex 真正恢复流畅。**

## 为什么会有这个 Skill

事情很简单：**Codex 前一天还正常，第二天打开突然开始卡。**

我们在 Windows 版 Codex 桌面端反复遇到过这种情况：

- 启动明显变慢
- 鼠标持续转圈
- 界面迟缓，甚至直接“未响应”
- CPU 占用却没有明显拉高
- 风扇也没怎么转

一开始我们以为只是版本更新后的初始化，忍一忍就过去了。

结果过几天，又来一次。

于是开始查。

网上也能找到不少类似反馈：启动缓慢、界面冻结、任务恢复失败、侧栏残留，以及 `no rollout found`。每个人的环境和根因可能不同，但有一个方向很值得查：

**Windows 上的 Codex 任务历史、会话存储和侧栏索引。**

后续实测又确认了第二个彼此独立的层级：**Chromium、Service Worker、代码和 GPU 缓存**。任务已经清空或归档，并不代表这些性能缓存也被清理。

我们随后对本机 Codex 做了两轮实际整理。

### 第一轮

永久删除 13 个已经确认没用的大任务，清理约 **338.60 MB** 会话文件。

重启 Codex 后，响应体验明显改善。

### 第二轮

直接做了一次完整审计：

- 共检查 **145 条任务记录**
- 其中 **131 条活动记录**
- 发现多条超大会话
- 还发现大量隐藏的 Guardian / 派生任务

最终处理结果：

- ✅ 保留 **6** 个活动任务
- 📦 归档 **16** 个仍有价值的任务
- 🗑️ 永久删除 **123** 个不再需要的记录
- 🧹 修复删除后残留的任务索引和侧栏幽灵条目

再次启动 Codex 后，活动列表干净了很多，损坏条目消失，任务浏览和日常使用也恢复顺畅。

### 第三轮：性能缓存

任务历史已经完成整理后，Codex 仍然出现从浏览器切回应用就短暂“未响应”、鼠标转圈和中文输入法被卡住的问题。只读审计发现约 **384 MB** 可重建的浏览器、Service Worker、代码和 GPU 缓存。

在完整保留登录、任务会话、Local Storage、IndexedDB 和项目文件的前提下，将这些缓存备份并重建后，启动和前后台切换恢复流畅。

这次结果说明：**任务历史清理和性能缓存清理必须分开审计、分开确认、分开验证。**

这两轮整理跑下来，我们把判断标准和操作顺序整理成了一套可复用流程，于是有了 **CodexCleaner**。

它主要处理这些本地问题：

- 任务历史越堆越多
- 超大会话占用空间
- 隐藏 Guardian / 派生记录残留
- 官方归档或删除后，侧栏索引没有同步
- `no rollout found` 一类疑似历史记录与索引不一致的问题
- Chromium、Service Worker、代码和 GPU 缓存异常膨胀或长期未重建
- 启动慢、切回 Codex 假死、鼠标转圈等可由缓存重建改善的性能问题

系统环境、网络、客户端版本等因素，仍然需要结合 Codex 常规诊断一起判断。

**CodexCleaner 的定位很明确：分别审计任务层和缓存层，确认后安全整理，再复核实际响应体验。**

它会先生成一份清晰的 **“保留 / 归档 / 永久删除”** 方案，等用户确认后，再调用 Codex 官方任务操作执行，并在最后复核本地存储和左侧任务列表。

## 左侧列表会发生什么

| 选择 | 左侧列表结果 | 任务历史 | 适用场景 |
| --- | --- | --- | --- |
| 保留 | 条目继续显示在活动列表 | 完整保留 | 正在进行或重要的工作 |
| 归档 | 条目从活动列表消失 | 完整保留，可取消归档恢复 | 已完成或暂停、仍值得保留的工作 |
| 永久删除 | 条目被移除 | 永久删除，并包含派生任务 | 明确不再需要的任务 |
| 修复过期索引 | 损坏或过期条目被移除 | 与实际存在的历史记录重新一致 | `no rollout found` 与缓存不一致 |
| 重建性能缓存 | 左侧任务不变 | 登录和任务历史保持不变 | 启动慢、焦点切换假死、界面转圈 |

### 清理范围

**项目目录、Git 仓库、源代码、文档和构建产物，都不在 CodexCleaner 的清理范围内。**

性能缓存模式还会明确保护 Cookies、登录状态、Local Storage、IndexedDB、Session Storage、WebStorage，以及 `$CODEX_HOME` 下的所有任务和会话数据。缓存只移动到带时间戳的备份，不直接永久删除。

默认情况下，更推荐使用 **归档**：

既能把活动列表清干净，又能保留以后继续或查阅需要的上下文。

**永久删除只适合已经明确确认、以后也不再需要的任务。**

## 判断标准

- **保留：** 当前工作、置顶任务、包含独特上下文，或近期还会继续的任务。
- **归档：** 已完成或暂停，但以后可能还要查阅、追溯或继续的任务。
- **永久删除：** 明确没用的测试、空任务、重复项、已结束的一次性工作，或会话文件已经不存在的损坏条目。
- **待决定：** 暂时无法判断的任务先不动，保持可恢复状态，交给用户决定。

一句话概括：

**能归档就先归档，永久删除必须明确确认。**

## 安装

把本目录克隆或复制到用户 Skill 目录：

```powershell
git clone <仓库地址> "$env:USERPROFILE\.codex\skills\codexcleaner"
```

Codex 通常会自动识别 Skill 变化。

如果新 Skill 没有出现，重启一次 Codex 即可。

## 使用

显式调用：

```text
$codexcleaner 审计我的 Codex 任务，建议哪些保留、哪些归档、哪些永久删除。执行任何变更前先展示完整方案。
```

性能排障：

```text
$codexcleaner Codex 启动和前后台切换很卡。分别审计任务历史和可重建性能缓存，执行前先展示清单并确认。
```

任务历史流程：

1. 先做只读审计。
2. 逐项给出建议，并统计任务数量和已知大小。
3. 分别确认归档清单和永久删除清单。
4. 使用 Codex 官方归档与删除操作执行。
5. 最后复核存储状态和左侧任务列表。

**任何实际变更，都应该建立在用户确认之后。**

性能缓存流程同样先审计，再要求用户确认并彻底退出 Codex；只处理固定允许列表中的可重建缓存，保留时间戳备份，重启后至少验证三次浏览器与 Codex 的焦点切换。缓存不做定时自动清理。

## 只读审计工具

项目附带一个只读审计脚本，只使用 Python 标准库：

```powershell
python scripts/audit_codex.py
python scripts/audit_codex.py --json
```

脚本只读取任务元数据和文件大小，**不会读取对话正文，也不会修改 Codex 数据。**

如需自定义数据库路径或受保护任务 ID：

```powershell
python scripts/audit_codex.py --help
```

性能缓存审计：

```powershell
python scripts/cache_maintenance.py audit
python scripts/cache_maintenance.py audit --json
```

用户从系统托盘彻底退出 Codex 后，可在外部终端执行已确认的清理：

```powershell
python scripts/cache_maintenance.py clean --apply --relaunch
```

也可使用可见的 `scripts\run_cache_cleanup.cmd`。它检测到 `ChatGPT.exe` 仍运行时会拒绝清理。

## 环境与范围

- Windows 10 或 Windows 11
- 当前版本 Codex CLI，具备 `doctor`、`archive`、`unarchive`、`delete` 命令
- 可选审计脚本需要 Python 3.9+

Codex 的任务存储属于可能随版本持续演进的实现细节。

所以 CodexCleaner 会优先使用官方任务操作。

直接数据库修复只作为单独确认的维护流程，并配套备份与完整性检查。

官方语义见 [Codex App Server API 概览](https://learn.chatgpt.com/docs/app-server#api-overview)。
